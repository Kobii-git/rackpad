# Rackpad v1.8.2-beta.4 upgrade and test notes

This security beta builds on `v1.8.2-beta.3` and preserves its Rack Studio,
patch-panel, and native deployment fixes. Docker remains the supported general
deployment; this release does not promote experimental native Proxmox support.

## Before upgrading

- Capture a database/volume and configuration backup. Retain the existing
  `RACKPAD_SECRET_KEY`; changing it makes existing encrypted credentials unreadable.
  If inline plaintext SNMP communities exist and no key was previously configured,
  configure a strong key before starting the new version. Missing-key conversion
  fails atomically before startup completes.
- Replace numeric/truthy `TRUST_PROXY` values with controlled proxy IPs/CIDRs.
  Legacy or invalid values disable trust with a warning. Keep forwarding headers
  overwritten at the public proxy and restrict direct access to the app port.
- Configure a trusted OIDC administrator subject or provider-controlled group.
  Email-based access and role decisions require boolean `email_verified: true`.
  Existing OIDC sessions are revoked, and roles are recomputed once at next login,
  including roles previously assigned manually. Verify recovery access beforehand.
- Plan explicit trap enablement and source credential reconfiguration where needed.
  Incoming observations no longer establish trust; device and monitor credential
  references remain intact.

## Migration and compatibility

Migration 50 follows the already-published rack-top migration 49. It encrypts
inline monitor communities, clears their plaintext column, adds the OIDC role
recheck marker, revokes existing OIDC sessions, and removes historical trap-source
community values and credential links. These changes commit together.

Legacy logical backups through schema 49 receive the same conversion during
restore. Current backups preserve ciphertext, explicit source mappings, and the
role recheck marker. Missing-key or malformed-secret failures roll back the restore.
Existing backups remain sensitive and are not deleted automatically.

Monitor community fields are write-only: omission preserves, a nonempty value
replaces, and explicit `null` clears the inline value. Responses return a presence
indicator instead of plaintext or ciphertext. TCP, ICMP, and SNMP retain private
IPv4/IPv6 LAN access while rejecting loopback, link-local, metadata, multicast,
reserved, and mixed allowed/blocked DNS answers.

## Acceptance and smoke checks

Run the complete repository, browser, screenshot, shell, dependency, and security
gates on the candidate before publication. Independently review authorization and
the migration/restore port. Use isolated temporary databases and injected transports
for negative security cases; never rehearse restores against live data.

After upgrading a disposable copy of an existing installation:

1. Sign in as the intended administrator, confirm a scoped viewer cannot read
   another lab, and verify OIDC completion rejects a different browser or replay.
2. Confirm enabled monitoring works for intended LAN targets and stored communities
   remain absent from responses. Rename a monitor without losing its secret.
3. Reconfigure source-level trap credentials, explicitly enable the listener/UDP
   exposure where needed, and verify only configured trust changes monitor state.
4. Verify schema-49 upgrade and legacy/current backup round trips, including
   atomic failure with a missing key. Check existing rack-top placement and
   dual-face patch-panel behavior remain intact.
5. Rotate previously exposed SNMP communities in Rackpad and on affected devices.

## Rollback and promotion

Rollback requires the matching prior application and pre-upgrade database and
configuration snapshot. Do not run beta.3 or an older binary against schema 50.
Publish this version to the beta channel as a prerelease. Stable promotion remains
subject to the existing product tester confirmations and native Proxmox guest
matrix/soak requirements; this security update does not claim those are complete.
