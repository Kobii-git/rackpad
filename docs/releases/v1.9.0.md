# Rackpad v1.9.0

This release brings room floorplans, checked device and cable references,
portable hardware templates, and expanded device face controls from beta to
stable. It also adds ntfy notification delivery, lab-scoped audit history, and
read-only inventory and health integrations. Docker on linux/amd64 and
linux/arm64 remains the supported deployment.

## Security and reliability

- Test & Discover and connection edits require a replacement credential when
  changing its destination or disabling TLS verification.
- External health records require a fresh observation from the configured
  provider before they can be bound. Imports check the binding's provider
  identity before treating a device as already adopted.
- A continuing outage without a recorded delivery remains eligible for its first
  enabled notification after an upgrade or restore.
- The release uses patched Fastify static serving and Hono dependencies for the
  MCP Node adapter. MCP and external health polling remain opt-in.

## Upgrade and rollback

Upgrading from v1.8.7 applies SQLite schema migrations 56–62. Take a consistent
pre-upgrade database or volume snapshot and keep it with your configuration,
original encryption key and matching previous image. After publication, pin
`RACKPAD_TAG=1.9.0`, pull the image, recreate the container, and verify login,
inventory, monitoring and restart persistence. Older installations should also
follow the [earlier upgrade precautions](../../INSTALL.md#before-upgrading-to-186).

Roll back using the previous image and its paired pre-upgrade snapshot. Plan how
to reconcile any inventory changes made after upgrading before restoring the
snapshot. Native Proxmox LXC remains experimental.

## Release validation

The candidate and published-image checks cover fresh setup, upgrade, restart and
paired rollback from the current stable and beta predecessors on both supported
architectures. Private-provider access and real Proxmox guest acceptance require
validation in the operator's environment.
