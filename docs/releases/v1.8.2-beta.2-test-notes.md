# Rackpad v1.8.2-beta.2 release test notes

## Status

Rackpad `v1.8.2-beta.2` is a combined beta candidate for issues #138 and #139.
It must not be tagged or published until the exact candidate passes the full
automated release gate and the disposable Proxmox guest matrix below. This work
does not submit Rackpad to Proxmox VE Helper-Scripts.

The candidate advances SQLite from schema 48 to 49. Existing rows require no
rewrite, but schema 49 can contain `rack-top` placement values that older
binaries cannot interpret. Preserve a pre-upgrade native backup or volume
snapshot; rollback after using rack-top placement requires restoring it with the
matching older image.

## Candidate changes

- Permit `AF_NETLINK` in the native base systemd unit while keeping `AF_PACKET`
  exclusive to opt-in advanced discovery.
- Apply hardware-template compatibility and nearest-default resolution across a
  custom device type's complete, cycle-safe parent lineage.
- Route Rack Studio cables through a shared deterministic planner with stable
  interval lanes, obstacle-aware exterior gutters, smooth and orthogonal output,
  exact manual waypoints, persisted preferences, and focused interaction.
- Add rack-top placement, validation, editing, backup/restore, Rack Studio and
  Rack Cabling scenes, exact port anchors, and screen/SVG/PNG output.

## Automated acceptance

- Run `npm run check:full` and `npm run screenshots:check` at the exact candidate
  commit. Inspect all command output and do not infer coverage from a silent or
  partial gate.
- Run Bash syntax and ShellCheck for the native installer, updater, dispatcher,
  environment, service, and discovery assets. The Proxmox fixture suite must
  verify exact safe and advanced address-family sets plus install, update,
  no-op, and rollback behavior.
- Confirm schema 48 to 49 migration, logical/native backup restore, rack-top
  overlap and undo/redo, inherited templates/default precedence, 14 or more
  active corridor routes, reordered-input stability, obstacle avoidance,
  manual anchors, both render styles, and identical screen/export planning.
- Review the systemd hardening and schema/backup changes independently before
  merge.

## Disposable Proxmox matrix

Repeat fresh-install and update testing on Proxmox VE 9.x AMD64 using an
unprivileged Debian 13 guest and an unprivileged Ubuntu 24.04 guest. Rackpad must
start without address-family error 97 and pass health, authentication,
collectors, backup/restore, password reset, safe discovery, advanced-discovery
preflight, update, rollback, reboot, and seven-day soak checks.

Record the PVE version, guest template, command outcome, and sanitized diagnostic
summary on issue #138. Automated local fixtures are necessary but are not
evidence that a real PVE guest passed.

## Product acceptance

- A custom child of `server` can discover, preview, and apply a server hardware
  template while retaining canonical ports, bindings, links, and snapshots.
- Dense Rack Studio cables remain individually traceable beyond the former
  modulo limit; hover/selection labels and fading work in both themes, and export
  uses the selected style and label setting.
- A switch can be placed above a rack without consuming rack U height, moved on
  the 12-column surface, cabled from exact front/rear ports, exported, restored,
  and carried with the rack when its room position changes.

## Publication and issue handling

The pull request must target `beta`, and all required checks must pass at its
exact head before merge. Tagging, pushing, publishing images/releases, and
posting issue comments require separate explicit authorization. Keep #138 open
through the renewed seven-day soak and first supported native-LXC release. Close
#139 only after the tester-like upgrade scenario confirms cable readability,
inherited templates, and rack-top placement.
