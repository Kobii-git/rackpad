# Rackpad v1.8.5

This release adds room/rack header colors and a per-device name position setting.
Docker on linux/amd64 and linux/arm64 remains the supported deployment. Confirm
this tag in GitHub Releases and the published GHCR image digest before installation.

## Highlights

- Set a room or rack header color in its editor. Rack Cabling fills the entire
  header and selects readable black or white text, including rack capacity.
  Reset restores the theme default (#195).
- Choose upper-left or upper-right device name placement in the device editor.
  Visualizer modes, Diagram, Racks, Studio and SVG/PNG exports use the preference.
  Names retain their existing readable screen size while zooming (#193).
- Logical/native backups preserve the new settings. Older logical backups use
  original presentation defaults; inconsistent native schema markers are rejected.
- Candidate image smoke tests derive the expected schema from the application
  declaration while keeping immutable previous-image upgrade/rollback baselines.

## Upgrade and rollback

Version 1.8.4 uses schema 54; v1.8.5 advances to schema 55. Existing room/rack
headers keep their theme colors and device names keep upper-right placement.
Migrations are forward-only.

Before upgrading, stop writes and retain a protected consistent database/volume
snapshot, configuration, the original `RACKPAD_SECRET_KEY` and matching previous
image together. Pin `RACKPAD_TAG=1.8.5` with the matching release manifest. After
upgrade, verify administrator access, lab boundaries, inventory, saved colors/name
placement, connected ports, monitoring and restart persistence.

Rollback restores the previous image with its paired pre-upgrade database,
configuration and key. Running an older image against schema-55 data is unsupported.
Older installations must also follow the [1.8.4 upgrade precautions](../../INSTALL.md#before-upgrading-to-184)
and any applicable earlier security guidance. MCP remains disabled by default;
its tokens are excluded from backups and revoked by restore.

## Release validation and limits

Publication requires the full quality gate, Chromium/Firefox acceptance, storage
compatibility, Net-SNMP interoperability, Linux container ownership checks,
documentation screenshot determinism, CodeQL and Trivy. The published immutable
image is checked on AMD64 and ARM64 for revision, fresh schema-55 startup,
authenticated writes/monitoring, actual schema-53 upgrade, restart persistence
and paired rollback before GitHub Release creation. Pre-merge candidate checks
also cover the stable schema-51 baseline on both architectures.

Reporter-environment confirmation for template editing, custom/round types and
Linux bind mounts remains external acceptance evidence. Native Proxmox LXC stays
experimental pending real-guest install/update/recovery testing. Skins, community
sharing and direct-rack rotation remain deferred.
