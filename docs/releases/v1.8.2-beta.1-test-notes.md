# Rackpad v1.8.2-beta.1 release test notes

## Status

Rackpad `v1.8.2-beta.1` is a beta candidate for the read-only Rack Cabling
Visualizer. Publication requires the exact candidate commit to pass the local
release gate and the pull request's quality, security, Docker, workflow, and
platform checks before merge and tagging.

No database migration, server route, public API, authorization rule, dependency
range, or stored inventory field changes are included. The lockfile resolves
`@fastify/rate-limit` and `fast-uri` to patched releases within their existing
ranges after new high-severity advisories were published. Rack Cabling adds
namespaced client preferences for its selected room, cable routing, labels, and
loose-tray state; no migration is needed. Existing Visualizer layouts remain
available and `grouped` remains the default. Rack Studio remains the only place
that can mutate rack placement or physical patching.

## Candidate changes

- Added a persisted `Rack cabling` layout and room selector with horizontally
  pannable, bottom-aligned rack elevations, exact front/rear physical ports,
  mixed rack heights, 12-column devices, shelves, side mounts, loose gear, and
  deterministic cross-rack cables.
- Added scene-scoped rack, device, port, and cable selection; inspection;
  direct-device navigation; search; trace; health and cable filtering; labels;
  keyboard shortcuts; focus restoration; responsive auto-fit; and read-only
  controls for every role.
- Added deterministic smooth and orthogonal routing with stable lane offsets.
  Cross-room, hidden-face, unavailable-position, and collapsed-tray endpoints
  use explicit labeled handoffs rather than inferred physical paths.
- Devices without a usable physical position remain visible. Configured
  faceplates are preserved under an unavailable-position warning, while a
  missing layout uses a distinct generic fallback.
- Handoff labels are sorted and packed into stable scene, rack, fallback, and
  tray lanes. Cable anchors remain exact and leader lines show displaced labels.
- Refreshed lockfile-only `@fastify/rate-limit` and `fast-uri` patch resolutions
  to clear high-severity findings. Fastify remains at the existing compatible
  resolution because its patched release removes numeric `TRUST_PROXY`;
  Rackpad's documented origin-isolation requirement remains the mitigation for
  the outstanding moderate advisory.

## Candidate evidence

- The clean release worktree passed `git diff --check`, lint, lint proof, all
  TypeScript projects, localization validation, 272 server tests, 70 client
  tests, configuration/Proxmox/documentation checks, production build, and the
  205.8 KB gzip initial-JavaScript bundle budget check.
- All 32 Playwright scenarios passed, including focused Rack Cabling and Rack
  Studio coverage plus the responsive, theme, accessibility, and overflow
  matrices. The canonical two-pass screenshot determinism check also passed.
- The tracked Rack Cabling documentation screenshot was regenerated through
  the deterministic harness and visually checked in light and dark dense-room
  scenarios. No unrelated baseline was regenerated to clear drift.
- The staged allowlist must contain only Rack Cabling, shared presentation,
  tests, documentation, translations, version, and release-note paths. Local
  databases, backups, caches, generated build output, and duplicate `* 2` files
  are excluded.
- The pull request must target `beta` and all required checks must resolve at
  its exact head before merge. The `v1.8.2-beta.1` tag must be created from the
  resulting exact `beta` merge commit.

- On a fresh disposable volume, verify health, bootstrap and login, displayed

  restart persistence, and viewer read-only access.

## Compatibility and rollback

- Existing rack, room, device, physical-layout, port, and `PortLink` records
  remain authoritative and unchanged. Saved Visualizer settings remain
  compatible, and removing the feature needs no storage cleanup.
- Rollback is image-only to `v1.8.2-beta.0`; this candidate adds no migration or
  database rollback step. Preserve the normal volume snapshot discipline even
  though the schema is unchanged.
