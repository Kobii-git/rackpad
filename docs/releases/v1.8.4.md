# Rackpad v1.8.4

This stable candidate brings the 1.8.4 beta series together with custom hardware
types, round templates and readable device names. Confirm the published tag and
image in GitHub Releases before installation. Docker on linux/amd64 and
linux/arm64 remains the supported deployment.

## Highlights

- Guided hardware templates support mixed port blocks, independent faces, module
  bays, artwork layers/colors and undo/redo while preserving item and port IDs.
- Create custom device types inline. Types inherit their parent's behavior.
  Round access-point templates have circular front/rear artwork and editable ports.
  Template saves leave applied device snapshots unchanged until preview/apply.
- Stack members can use independent templates while retaining connected ports.
- Rack Studio and Rack Cabling share saved cable routing, brush-panel guides,
  multi-room layouts and SVG/PNG exports. Device names stay at 12 screen pixels
  while zooming, use the physical upper-right corner, and reveal full names on
  hover/focus when truncated or hidden for lack of space.
- Collision rejection preserves both placements atomically. Existing legacy
  overlaps remain selectable and can be moved into free space.
- MCP is an explicit opt-in, with scoped expiring personal tokens and create-only
  proposals that a person reviews before applying. It remains disabled by default.

## Upgrade and rollback

Stable 1.8.3 uses schema 51. Version 1.8.4 uses schema 54: routing metadata (52),
MCP tokens (53), and stack-member layouts (54). Migrations are forward-only.

Before upgrading, stop writes and retain a protected consistent database/volume
snapshot, configuration, original `RACKPAD_SECRET_KEY` and the matching previous
image together. Pin the released `1.8.4` image and matching manifest. Verify
administrator access, lab boundaries, inventory, connected ports, monitoring and
restart persistence. Rollback restores the complete pre-upgrade pair; never run
an older binary against schema-54 data. MCP tokens are excluded from backups and
revoked by restore. Optional round-shape JSON metadata may be dropped by older
binaries if they rewrite layouts.

Bind mounts keep host ownership. Service-level Compose `user: "UID:GID"` requires
matching writable data-directory and database/WAL/SHM ownership. `PUID`/`PGID` do
not remap the image user, and Rackpad does not change host ownership. Follow the
[installation and upgrade guide](../../INSTALL.md#before-upgrading-to-184).

## Validation and remaining acceptance

Promotion requires the exact candidate's quality, browser, Linux storage,
Net-SNMP, screenshot, CodeQL and Trivy checks, plus unpublished image smoke on
AMD64 and ARM64. Image checks exercise fresh installation, actual schema-51 and
schema-53 upgrades, authenticated writes/monitoring, restart persistence and
rollback using separate pre-upgrade snapshots. Use the candidate PR's Actions
results for evidence; these notes do not imply that a prepared tag is published.

Reporter-environment confirmation for template editing and Linux bind mounts
remains external acceptance evidence. Native Proxmox LXC stays experimental
pending real-guest install/update/recovery testing. Skins, community sharing,
occupied-slot swapping and direct-rack rotation remain deferred.

The narrow SNMPv3 protocol exception retains its source hash, exact locations,
owner and November 30, 2026 expiry. Other high/critical CodeQL findings and fixable
high/critical dependency/image findings block publication. This is not a claim of
zero total vulnerabilities.
