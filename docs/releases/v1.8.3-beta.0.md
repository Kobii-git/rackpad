# Rackpad v1.8.3-beta.0 combined candidate

Beta candidate combining maintenance, stabilization, stacked switches, and SNMPv3 repairs.
The intended stable release is **1.8.3**, after acceptance. Docker remains the
supported general deployment; native Proxmox LXC remains experimental.

## Changes

- SNMPv3 RFC key localization and AES128 privacy encoding, authenticated response
  validation, correlated discovery, bounded engine-time synchronization, and
  authenticated trap security levels/timeliness. Stored credentials are retained.
- Focused Chromium/Firefox Storage regressions for unavailable/throwing UUID APIs
  on fresh and schema-50-upgraded data, plus real Net-SNMP interoperability in CI.

- Ordered stacked-switch members, metadata and labelled MAC addresses, nullable
  canonical port assignments, derived physical layouts, and lab-scoped member APIs.
  Existing ordinary switches and their port/link identities remain unchanged.
- Rack Studio unmount, undo, redo, and loose-room moves return canonical placement
  state while retaining the stack's derived height in storage. Genuine concurrent
  changes still return a conflict.
- Mixed-face/rear cable continuation rendering and exports, plus deterministic
  documentation screenshots required after application checks in reusable quality.
  Screenshot raster settings preserve automatic frames on Linux; the inherited
  manual-frame flag was reproduced stalling readiness and removed.
- Docker installer uses the channel-aligned release manifest, preserves existing
  configuration and keys, quotes supplied keys exactly, and verifies Compose key
  readback before pulling images or replacing configuration. Custom Compose files
  receive a proposal; recognized managed files receive a protected backup.
- Native readiness uses a shared 60-second deadline for bounded systemd and HTTP
  calls, strict health JSON, and post-readiness authentication, SPA, and collector
  checks. Failed activation restores the paired application, database and config.
- Publication requires quality, CodeQL findings, and security gates; tagged releases
  consume this notes file. Operator guidance and dependency grouping are refreshed.

The existing stack interfaces are retained. Remediation adds no further API or
environment-variable names and does not change deployment exposure defaults.

## Upgrade and recovery

The candidate starts at published beta.5 commit
`767d50764a3e0173ca71cdb6c56d342a43a7ccb5`. Published migrations **49 and 50 are
unchanged**; stack migration **51** is appended. Schema and restore manifests use
51. Security conversion remains at the schema-50 boundary, including old-backup
conversion. Repeat startup at 51 must leave data unchanged.

Before upgrading, save the previous application artifact and a matching database,
configuration and encryption-key snapshot. Preserve `RACKPAD_SECRET_KEY` exactly;
losing it makes existing encrypted credentials unreadable. Missing-key conversion
of legacy inline communities fails atomically. See the retained
[security upgrade instructions](v1.8.2-beta.4-test-notes.md) for trusted proxy IPs,
OIDC re-login and role recalculation, trap-source reconfiguration, and community
rotation. Traps remain explicitly opt-in.

Rollback restores the **previous application with its pre-upgrade database and
configuration**. Older binaries must never open schema-51 data. A current logical
export cannot substitute for the pre-upgrade database snapshot when downgrading.
Logical and native restores must reject newer schemas or invalid ownership without
changing the destination. Keep backup retention and original keys unchanged.

commit, package version, image digests for both architectures, source-asset hashes,
guest OS, PVE version, discovery mode, timestamps, and pass/fail evidence together.

      advertised access information.

      refusal, and separately opted-in traps. No outer privilege changes.

      secret output. Confirm keys survive update, reboot, restore and rollback.

      atomically. Restore only disposable data.

## Publication-gate remediation

Hosted quality at commit `8fa95c3e5a180f74d3797ef8932836ae09870719` passed the
full application gate, Chromium/Firefox Storage cases, real Net-SNMP
interoperability, screenshot determinism, and shell/PowerShell/workflow checks.
Hosted filesystem/image scans also passed. CodeQL reported two high-severity
password-hashing findings at the RFC 3414 wire-key operations and prevented the
image build and release jobs from running.

The reviewed exception policy is limited to those two exact locations and binds
the source-file hash, unchanged server tree, owner and expiry at
**2026-11-30 00:00 UTC**. Independent protocol review established that the hashes
are required for configured SNMP interoperability; password storage remains
separate. Changed source or missing evidence disables the exceptions. Dates and
source identifiers must never be renewed automatically.

Raw CodeQL analysis remains complete and is retained with an explicit review
summary. Only eligible findings may be omitted from the separate uploaded report.
Malformed analysis, additional blockers and report-upload failures stop
publication; policy failures upload the raw results. No repository-wide hashing
exclusion or severity reduction is introduced.

Independent review found and reproduced malformed-report filtering and stale
summary defects in the initial policy implementation. The fixes validate complete
raw input against the pinned official SARIF schema and use separate evidence for
every invocation. The validator is development tooling; runtime SNMP code is
unchanged. All 12 publication regressions and actionlint passed, and the reviewer
confirmed both defects no longer reproduce.

After those repairs, clean `npm ci` and the standard application gate passed:
344 server tests, 92 client tests, 46 configuration/publication/installer cases,
30 native fixtures, documentation contracts, lint/type checks and production
build/bundle validation. npm audit found zero vulnerabilities. Runtime dependency
name/version sets are unchanged by the development-only validator additions.

The GitHub API-exported report identifies the two reviewed locations but contains
schema-invalid transformed fields, so it cannot substitute for native raw CodeQL
output. The changed workflow must pass against freshly generated hosted output
before publication; invalid reports remain blocking. Earlier green quality runs
do not establish that the new reporting workflow works on GitHub.
