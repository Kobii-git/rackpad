# Rackpad v1.8.1-beta.2 release test notes

## Status

Experimental tester candidate prepared on 2026-08-30. Publication and automated
release evidence make the exact tag available for testing; they do not prove a
real Proxmox installation or complete Phases 4 or 5.

## Beta 2 fixes

- Carry the explicitly authorized prerelease state from the host runner into
  the guest installer, allowing the exact beta tag to pass its native build and
  operational-asset validation.
- Compare current and candidate releases with SemVer precedence before any
  candidate download. Permit `v1.8.1-beta.1.1 -> v1.8.1-beta.2` and
  `v1.8.1-beta.2 -> v1.8.1`, but reject an older or equal non-no-op target.
- Publish the experimental procedure in `docs/PROXMOX_NATIVE_LXC.md` and issue
  #138 with explicit privacy, support, and production-use boundaries.

## Automated release evidence

Record after validation and publication:

- exact beta commit and quality, CodeQL, and security workflow URLs;
- immutable tag object and tag commit;
- tag workflow quality, image, and GitHub Release jobs;
- formal prerelease and source archive URLs;
- public GHCR `1.8.1-beta.2` digest and platform manifests;
- tagged package version, dispatcher/helper assets, and Community core pin.

Local candidate validation on 2026-08-30:

- Bash syntax, ShellCheck, actionlint, the production dependency audit,
  `check:docs`, and `check:proxmox` passed. The Proxmox gate checked 16 paired
  assets and 14 isolated fixture scenarios.
- The non-browser portion of `check:full` passed with 253 server assertions, 41
  client tests, configuration contracts, build, and bundle validation.
- The first combined browser run exhausted the long accessibility matrix's
  30-minute timeout and left two later routes loading. In clean targeted
  processes, the two fallout scenarios passed in 8.4 seconds and the complete
  responsive/accessibility matrix passed in 25.4 minutes. The exact-commit
  GitHub quality job remains mandatory before tagging.

## Real Proxmox evidence still required

Use the exact checklist in `docs/PROXMOX_NATIVE_LXC.md` and record pass, fail, or
not tested for each item without including private addresses or secrets.

### Debian 13 fresh install

- PVE 9.x `amd64`; unprivileged LXC with nesting; 2 CPU, 4 GiB RAM, 16 GiB disk,
  DHCP, and port 3000.
- Native build, active service, HTTP health/auth/SPA/collector checks, first
  administrator, ownership, hardening, reboot, and custom port.
- Backup, offline restore, password reset, safe discovery, advanced-mode success
  or truthful refusal, and UDP 1162 closed.

### Ubuntu 24.04 fresh install

- Repeat the critical Debian checklist using the alternative guest selection.

### Beta 1.1 to Beta 2

- Forward prerelease update, configuration/data preservation, versioned helper
  and core-pin refresh, and same-target no-op without restart.
- Pre-downtime build/download and snapshot failures, post-activation health and
  unit failures, paired rollback, recovery, retention cleanup, and reboot after
  both success and rollback. Failure injection is maintainer-only and must use
  disposable guests.

### Soak

- Retain successful Debian and Ubuntu guests and complete seven uninterrupted
  days of normal monitoring, backup, integration-status, and discovery work.
  Material fixes reset the affected validation and soak period.

## Boundaries

- Docker remains recommended; Beta 2 is not supported production software.
- Do not merge to `main`, publish stable `v1.8.1`, or claim Phase 4/5 completion
  until the missing real-PVE evidence is recorded and reviewed.
- Keep issue #138 open until the official Community Scripts submission is
  accepted.
